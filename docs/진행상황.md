## 1. 지금까지 한 일

### 설계 (10/27 ~ 10/29)
- 유스케이스, 시스템 구성도, 요구사항·화면 설계서(엑셀), ERD, 출석 시퀀스, 클릭 가능한 화면 목업.
- 사용자 결정 사항 반영: Tailscale Funnel(도메인 없음), 대리 출석 시 기기 주인 유지·다른 계정 자동 취소, 불이익(벌점·수료 불가·출석 취소), 출결 변경 10분 무응답 시 우선 거절, AI 모니터 제외(예산 없음), 이메일 계정은 첫 설정 화면에서 입력, GitHub 공개 저장소(비밀 정보 제외), 서비스 이름 "🎓 IoT 혁신융합대학 비교과 출석체크"와 로고.

### 구현 (10/29)

**API 서버 · Worker** (`apps/api`)
- 로그인: 학생(학교·학번·이름), 인솔자(직번·이름 → 학교 코드 4자리, 5회 틀리면 처음부터), 총관리자(아이디·비밀번호·OTP). 세션 3시간.
- 기기 확인: 처음 로그인한 브라우저를 등록 기기로. 다른 학생의 등록 기기면 등록하지 않음.
- 출석 판정: ① 시간 ② 거리(GPS 오차 최대 50m 보정) ③ 강의실 코드(30초마다 바뀜, 저장하지 않고 계산) ④ 대리 출석(기기 주인 유지) ⑤ 등록 기기(아니면 승인 대기).
- 기기 승인·거절(승인 시각 기준 출석·지각·결석), 출결 변경 신청·승인·10분 우선 거절·재검토, 문의(학생→인솔자→총관리자 이관).
- 엑셀: 학생·수강, 인솔자, 장소, 수업 일정 템플릿 → 미리보기(행별 오류) → 확정. 출석 현황 엑셀·CSV 다운로드.
- 첫 설정(총관리자 계정 → OTP → 이메일 테스트 → 완료), 이메일 설정 변경. 이메일 비밀번호는 암호화해 DB에 저장.
- 이메일 알림: 기기 승인 요청, 새 문의, 대리 출석 감지, 출결 변경 신청·결과·우선 거절, 장애.
- Worker(1분마다): 끝난 수업 자동 결석, 10분 우선 거절, 이메일 재발송(3회), 상태 점검. 매일 03:00 DB 백업(7일 보관).

**화면** (`apps/web`)
- 학생: 로그인, 동의, 출석 메인, 코드 입력, 결과(출석·지각·실패·승인 대기·출석 취소), 문의. 모든 화면 상단에 로고·"문의" 버튼.
- 인솔자: 2차 인증, 출석 현황(필터·다운로드·출결 변경 신청), 강의실 코드 화면(빔프로젝터), 기기 승인, 문의함, 학생·수강 관리(기기 초기화, 전체 학생 수강 등록), 엑셀 등록.
- 총관리자: 첫 설정, 로그인, 대시보드(남은 시간 표시), 출결 변경 승인(대기·재검토·완료), 전체 출석 현황, 문의, 기기 승인, 계정·학교 코드, 장소·일정, 엑셀 등록, 이메일 설정.

**운영 준비**
- Docker Compose(PostgreSQL 16, Redis 7, API, Worker, Nginx), Nginx 입구 두 개(공개 8080 / 관리자 8081, 관리자 API는 비밀 헤더로 이중 잠금).
- 공개 저장소 보안: `.gitignore`(비밀 값·DB·백업·엑셀 제외), `.env.example`, 커밋 전 비밀 정보 검사(gitleaks 훅), GitHub 올릴 때 자동 검사.
- [README](../README.md): 서버 PC 설치 순서, 출시 전 점검표, 자주 하는 일, 개발 PC 실행 방법.

### 검증
- 자동 테스트 26개 통과 (`npm test`): 출석 시간 경계값, 거리 보정, 강의실 코드, 첫 설정·로그인, 판정 ①~③ 실패, 대리 출석 두 경우(주인이 먼저 / 다른 계정이 먼저), 기기 승인, 출결 변경과 10분 우선 거절, 엑셀 미리보기·확정, 다운로드.
- 브라우저 확인(시연 데이터): 학생 로그인 → 동의 → 출석 성공, 같은 폰으로 다른 계정 출석 → 자동 출석 취소 화면, 총관리자 첫 설정 화면 이동.
- 빌드: API·화면 모두 통과 (`npm run build`).

- 좁은 화면에서 인솔자 출석 현황 표 아래쪽(인원·다운로드 버튼)이 표와 함께 가로로 밀림.
