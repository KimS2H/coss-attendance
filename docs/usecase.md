## 확정된 설계 결정

| 항목 | 결정 |
|---|---|
| 서비스 이름 | 🎓 IoT 혁신융합대학 비교과 출석체크. 모든 화면 상단에 IoT COSS 로고 (2026-10-29) |
| 서버 | 사무실 PC 1대 + Tailscale Funnel(고정 HTTPS 주소 `○○.ts.net`, 도메인·포트 개방 없음) + Docker Compose (개발 PC와 서버 PC는 별개) |
| 출석 판정 | GPS(건물 범위) + 강의실 코드(4자리, 30초마다 변경)를 함께 사용 |
| 기기 확인 | 처음 접속한 브라우저에 서버가 기기 쿠키(`did`)를 주고, 최초 로그인 기기를 계정에 묶음. 같은 쿠키로 다른 계정이 출석하면 대리 출석으로 판정 (GPS·코드와 함께 사용) |
| 총관리자 접속 | 인증된 기기(Tailscale)에서만 접속 + ID/PW. 로그아웃 전까지 유지 (OTP는 2026-10-30 없앰) |
| 인솔자 로그인 | 학생과 같은 공동 로그인 화면 → 2차 인증으로 학교 코드 4자리 입력 (학교별 고정, 총관리자만 변경) |
| 미등록 기기 | 인솔자 승인 후 출석 인정. 로그 기록 + 담당 인솔자에게 화면 알림·이메일. 출석·지각 판정은 승인 시각 기준 (수업 종료 후 승인이면 결석 유지) |
| 출석 규칙 | 시작 5분 전 ~ 5분 후 출석, 이후 종료까지 지각, 종료 후 결석. GPS 반경 기본 50m |
| 수업 구성 | 하루 여러 교시, 교시마다 장소가 다를 수 있음 |
| 알림 · 보유기간 | 알림은 이메일. 개인정보는 프로그램 종료 후 1년 뒤 파기 |
| 기술 스택 | TypeScript: React(반응형·PWA) + NestJS. 휴대폰·태블릿·노트북 지원 |
| 미등록 기기 경고 | "등록되지 않은 기기예요" + 빨간 느낌표 "해당 기기의 아이디가 아니에요" + "대리 출석의 경우 벌점, 수료 불가, 출석 취소 등 불이익이 있습니다. 같은 기기로 두 계정이 출석하면 기기 주인이 아닌 계정의 출석이 취소됩니다." |
| 대리 출석 · 불이익 | 같은 수업에서 같은 기기로 두 계정이 출석하면 기기 주인이 아닌 계정을 자동 출석 취소 (주인은 순서와 관계없이 유지, 둘 다 주인이 아니면 두 번째 계정 취소). 불이익: 출석 취소(자동) / 벌점 / 수료 불가(총관리자 결정) |
| 출결 변경 | 인솔자는 직접 바꾸지 않고 신청만 함. 총관리자가 승인·미승인한 뒤 반영. 10분 안에 답이 없으면 우선 거절하고, 총관리자가 나중에 재검토해 승인할 수 있음 |
| 문의·오류 신고 | 학생 문의 → 인솔자 처리(어려우면 총관리자 이관) / 인솔자 문의 → 총관리자. 기존 이의신청은 문의로 통합. 모든 기록은 총관리자 열람 |
| AI 모니터 | 사용하지 않음 (예산 없음). 상태 점검 + 이메일 알림 + Docker 자동 재시작으로 대응 (2026-10-29) |
| 이메일 발송 계정 | 총관리자가 첫 설정 화면에서 입력. 코드·저장소에는 넣지 않음 (2026-10-29) |
| 코드 저장소 | GitHub 공개 저장소. 비밀번호·키·DB 내용·실제 접속 주소는 올리지 않음 (2026-10-29) |
| 위치정보법 · 학교 네트워크 | 비영리·한시 사업, 좌표 미저장 → 별도 신고 없이 진행 / 학교 네트워크 사용 허용 |

## 액터

| 액터 | 설명 |
|---|---|
| 학생 | 비교과 참가 대학생 (40~50명) |
| 인솔자 | 학교별 담당자 (학교당 3명 이상). 담당 학교 데이터만 접근 |
| 총관리자 | 서버 관리자. 모든 학교 데이터 접근 |
| 운영자 (추상) | 인솔자와 총관리자가 함께 쓰는 기능을 묶은 액터. 실제 계정은 아님 |
| 스케줄러 (시스템) | 정해진 시각에 자동 작업 실행, 1분마다 상태 점검 |

## 유스케이스 목록

### 학생

| ID | 유스케이스 | 내용 | 관계 |
|---|---|---|---|
| S01 | 로그인 | 공동 로그인 화면에서 "학생" 선택 후 학교(선택), 학번, 이름 입력. "사용자 저장"은 입력값만 기억 | S03 포함 |
| S02 | 개인정보·위치정보 동의 | 최초 로그인 시 1회. 동의 이력 저장. 위치 동의를 안 하면 출석이 "위치 없음"으로 실패하므로 문의 → 인솔자 출결 변경 신청으로 처리 | S01 확장 (최초 로그인일 때) |
| S03 | 기기 확인·등록 | 최초 로그인 기기를 계정에 묶음 (그 기기가 다른 학생의 등록 기기면 묶지 않음). 다른 기기로 출석하면 "기기 승인 대기"로 저장되고 인솔자 승인 후 인정 | — |
| S04 | 오늘 수업 조회 | 상단에 "한국대 컴퓨터공학과 홍길동(20231234)", 버튼 위에 "0교시 \| 과목명" 표시. 하루 여러 교시 목록. 날짜는 서버 기준이며 변경 불가 | — |
| S05 | 출석하기 | 버튼 1회. 판정 후 버튼 비활성화되고 "출석" 표시 | S03·S06·S07 포함 |
| S06 | GPS 위치 확인 | 수업 장소 좌표와 거리 비교, 허용 반경 안이면 통과 | — |
| S07 | 강의실 코드 입력 | 인솔자 화면의 4자리 코드 입력 | — |
| S08 | 문의·오류 신고 | 모든 학생 화면 상단의 "문의" 버튼과 실패·승인 대기 화면의 링크로 들어감. 분류(출석 불가·위치 인식 불가·코드 입력 불가·로그인 불가·기기 변경·분실·수업 정보 오류·기타) 선택 후 문의. 기기 정보·마지막 시도 결과 자동 첨부. 답변·상태 확인 | S05 확장 (실패할 때) |
